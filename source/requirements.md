# GinyScreen 需求说明（v2.0.0）

> v1.x 的历史需求见 CHANGELOG。本版为「完全重建」后的目标与边界。

## 项目目标
做一个**自托管、零外置依赖**的屏幕共享工具：房间内谁都能开播，其他人跟着看，
适合「一起看视频 / 电影 / 游戏画面」，支持系统声音；不同类型设备（Windows/macOS/Linux/手机/平板）都能用。

## 核心需求

### R1 联机（本次重建的核心）
- R1.1 **零外置软件**：开房者启动后自动打通公网入口（UPnP-IGD / NAT-PMP），好友用浏览器打开地址即可加入；
  不得要求安装 VPN/组网/穿透工具。
- R1.2 支持四条路径并按可用性自动组织：**局域网 → IPv6 → 公网端口映射 → 内置中继**。
- R1.3 提供**网络诊断**：逐项显示局域网/IPv6/公网/NAT 类型/中继状态，并给出人话建议。
- R1.4 传统组网/穿透（Radmin、蒲公英、SakuraFrp）保留为**高级备选**入口与文档。

### R2 屏幕共享
- R2.1 可共享整屏 / 窗口 / 标签页（桌面版内置选择器），可选系统声音。
- R2.2 **双链路**：
  - 标准链路（WebRTC）：低延迟；编解码优选；每位观看者独立码率自适应；失败自动重建。
  - 影院模式（WebCodecs + 服务器中继）：画质恒定、弱网平滑；支持关键帧请求与码率反馈。
- R2.3 画质档位：自动 / 电影 1080p30 / 游戏 1080p60 / 文字（原生分辨率）/ 省流 720p30，共享中可实时切换。
- R2.4 停止共享以服务器状态为准；多人同时共享时多宫格展示、点击聚焦。

### R3 观看体验
- R3.1 主画面：全屏、系统级画中画、画面比例（自适应 / 16:9 / 原始 / 拉伸）、每格独立音量。
- R3.2 **质量面板**：分辨率/帧率/码率/RTT/丢包/直连或中继/拥塞原因 + 趋势图。
- R3.3 响应式：桌面三栏；手机竖屏单栏、触摸操作、全屏、安全区域适配。
- R3.4 PWA：可安装到桌面/主屏；离线可打开界面。

### R4 房间与邀请
- R4.1 单服务器单房间（`main`），昵称即进，无需注册。
- R4.2 邀请面板：局域网 / IPv6 / 公网 / HTTPS 多地址 + 一键复制 + 二维码（服务端生成）；房间内可扫码进入。
- R4.3 桌面版支持「本机开房 / 连接朋友的房间」切换，保存后自动重启进入。

## 非功能需求
- N1 **安全上下文**：localhost 与桌面版天然满足；局域网其它电脑通过自动生成的自签名 HTTPS 满足。
- N2 **隐私**：标准链路端到端加密（P2P 或中继均是密文）；影院模式经服务器转发（声音仍端到端加密）。
- N3 **零配置**：服务器 `npm install && npm start` 即可跑；客户端无构建步骤。
- N4 **规模**：mesh 适合 2~4 人共享/观看（房间上限 12 人）；更大规模走 SFU 升级路径（docs/tech-alternatives.md）。
- N5 **可诊断**：任何联机/画质问题都能在网络诊断与质量面板里看到可解释的原因。

## 验收标准（v2.0）
1. 同一局域网两台设备：直接用局域网地址加入，共享可看。
2. 跨网络：优先公网/IPv6 地址；不可用时游戏内中继兜底可看。
3. 网络诊断页面对每种状态给出正确的结论与建议。
4. 标准链路与影院模式都能共享并观看；质量面板显示实时指标（含「直连/中继」）。
5. 手机扫码进入可观看（竖屏、全屏可用）。
6. `npm test`（26 项断言）全部通过。

## 范围外（路线图）
- SFU 扩容（>8 人）、录制/回放、远程控制、房主权限体系、账号与好友系统、移动端采集（系统限制）。

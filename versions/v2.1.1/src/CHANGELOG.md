# CHANGELOG

本项目遵循语义化版本（Semantic Versioning），版本号以根目录 `VERSION` 文件为唯一来源。
版本发布流程见 `VERSIONING.md`。

## [v2.1.1] - 2026-09-29

### 修复
- **全屏在所有设备可用**：改为三级策略 —— ① 原生 Fullscreen API；② iOS Safari 用 `<video>` 原生全屏；
  ③ 都不可用时用 **CSS 伪全屏**兜底（固定覆盖视口 + 右上角「✕ 退出全屏」+ Esc 退出）。
  底部工具栏新增「⛶ 全屏」按钮（此前只有悬停工具栏里有，手机没有 hover 很难发现）。
- **IPv6 联机修复（关键）**：内置中继此前**只监听 IPv4**，双方都是 IPv6 时一旦 P2P 打洞失败就没有中继兜底 →
  表现为「都有 IPv6 却连不上」。现在改为 **IPv4 + IPv6 双栈监听**；中继地址按分配协议族选择
  （显式请求 IPv6 → 绑定双栈并通告本机全局 IPv6；IPv4 分配不再传 `ip:'::'` 以避免 508 分配失败）。
- **手机端体验**：
  - 成员按钮改为**始终渲染**（显示与否交给 CSS），窄窗口/平板/手机都能打开成员列表（此前按 UA 判断，非手机 UA 时按钮被移除）
  - 触摸设备（`hover: none`）工具栏**常显**，点击区域加大，避免「找不到全屏/画中画按钮」
  - 修复手机浏览器地址栏伸缩导致底部被裁掉（`100dvh` 动态视口高度）
  - 禁用双击缩放误触（`touch-action: manipulation`）
- **网络诊断更诚实**：IPv6 条目明确提示「对方打不开多为路由器 IPv6 防火墙拦截入站，可改用公网 IPv4/中继」；
  新增「连不上时先查 Windows 防火墙」提示（含房间端口与中继端口）；中继条目显示双栈与 IPv6 地址。
- **邀请地址更干净**：局域网与 IPv6 各只列前 2 条（过滤 Clash 等虚拟网卡的 `198.18.x` 网段），
  IPv6 按接口优先级排序（WiFi/以太网优先，VPN/虚拟网卡靠后），避免好友挑错地址。
- **桌面版**：「连接朋友的房间」现在支持直接粘贴**裸 IPv6 地址**（自动补方括号，如 `240e:xxxx::1`）；
  地址输入框提示补充 IPv6 写法。

## [v2.1.0] - 2026-09-29

### 重大变更（品牌更名）
- **软件更名为 Gracs（GRACS · 格瑞克斯）**，原名 GinyScreen：
  - 全称：**Ginyva Remote Access Cross-network Screen-sharing Solution**（Ginyva 远程接入 · 跨网络 · 屏幕共享方案）
  - 缩写 **GRACS**：G（Ginyva）+ R（Remote 远程）+ A（Access 接入）+ C（Cross-network 跨网络）+ S（Screen-sharing 屏幕共享 / Solution 方案）
  - 品牌写法 **Gracs**，读音 /ɡræks/（中文近似「格瑞克斯」）
- **界面与文案**：浏览器/桌面版标题、品牌名、关于面板（含全称、缩写、读音）、托盘与弹窗、启动横幅、安装包与产物名全部更新
- **打包产物更名**：`Gracs-Debug-vX.Y.Z.exe` / `Gracs-Portable-vX.Y.Z.exe` / `Gracs-Setup-vX.Y.Z.exe`
- **技术标识**：npm 包名 `gracs`、Electron `appId` `com.gracs.app`、`productName` `Gracs`、TURN 域与软件标识 `gracs`、
  自签证书 CN `Gracs`（地址指纹变化会自动重签）、Service Worker 缓存名 `gracs-*`
- **更新链路**：清单源同时包含新仓库 `GinyvaXu/Gracs` 与旧仓库 `GinyvaXu/GinyScreen`（兜底），仓库更名期间新旧版本都能取到更新

### 升级与迁移说明（重要）
- 由于应用 ID 与安装目录名变化，**安装版升级后会出现新旧两份程序**（`Gracs` 与 `GinyScreen` 并存）：
  新版本可正常使用，请在确认无误后手动卸载旧的 GinyScreen，避免混淆。
- 桌面版连接配置目录随应用名变化（`%APPDATA%\Gracs`），首次启动需重新填写一次「开房间 / 连接朋友」设置；
  浏览器版与局域网/公网地址不受影响。
- 建议的发布顺序：**先在旧仓库名下发一版 v2.1.0**（让老客户端能自动升级），**再把 GitHub 仓库更名为 Gracs**。

## [v2.0.1] - 2026-09-28

### 修复
- **全屏 / 画中画 / 音量滑块无效**：瓦片工具栏按钮的回调引用了尚未定义的对象，点击即抛 `ReferenceError` 而静默失败；
  重构瓦片创建流程（先建对象再挂事件）后三者全部可用；影院模式（canvas 画面）不再显示无效的「画中画」按钮。
- **系统声音采集更稳**：屏幕采集的音频请求改为最稳的 `audio: true`（不同浏览器/Electron 对「带约束的音频请求」
  处理不一致，可能拿到不带音轨的流），需要关闭音频处理时改为**采集后**再尝试 `applyConstraints`。
- **拿不到声音时给出可操作原因**（按共享来源区分）：共享「窗口」提示改选「整个屏幕」；共享「标签页」提示勾选标签页音频；
  其它情况提示在系统弹窗里勾选「共享系统音频」。共享状态栏新增「🔊 系统声音 / 🔇 无系统声音」。

### 新增
- **质量面板显示声音状态**：每位观看者（共享者视角）或每路画面（观看者视角）新增「声音」一行，
  显示实时音频码率（如 `🔊 32 kbps`）或「🔇 无音轨」；影院模式的独立音频连接也会合并显示。
- 桌面版日志新增屏幕采集的音频决策记录（页面是否请求音频 / 来源类型 / 是否走 loopback 回环采集），便于排查。

## [v2.0.0] - 2026-09-28

### 重大变更（完全重建）
- **零外置软件联机**：内置 STUN/TURN 中继 + UPnP/NAT-PMP 自动端口映射 + IPv6/局域网自动直连，
  开房后自动打通公网入口，好友用浏览器打开地址即可加入 —— **不再需要 Radmin / ZeroTier / 蒲公英 / 内网穿透**。
  传统组网方案降级为「高级备选」，入口保留。
- **双链路屏幕共享**：
  - **标准链路（WebRTC 深度优化）**：编解码智能优选（AV1→VP9→H.264→VP8）、每位观看者独立码率自适应、
    入房即请求关键帧、失败自动重建连接、实时质量可观测。
  - **影院模式（新，WebCodecs + 服务器中继）**：编码参数完全可控，画质恒定不抖动、弱网平滑，
    专为「一起看电影」设计；声音仍走 WebRTC（Opus）。
- **连接质量可视化**：新增「📶 质量」面板，实时显示每位观看者/每路画面的
  分辨率、帧率、码率、RTT、丢包、P2P 直连/中继、拥塞原因（带宽/CPU），配迷你趋势图。
- **网络诊断（连接医生）**：一页看懂局域网 / IPv6 / 公网映射 / NAT 类型 / 中继状态，
  每条结论都带「怎么办」；支持深度检测（RFC 5780 NAT 类型）。
- **界面重做**：全新响应式 UI（深色影院风），移动端/平板观看优化（竖屏、触摸、安全区域），
  邀请面板（多地址 + 二维码）、扫码加入、PWA 可安装到桌面/主屏。

### 新增
- 内置 TURN 中继（纯 JS，零外置依赖）：HMAC 临时凭据（4 小时自动失效）、按分配来源自动选择中继通告地址
  （多网卡/VPN 环境不会通告错地址）、端口配额与限流、UDP+TCP 双通道。
- 内置 STUN 服务（与中继同端口）：观看者用它探测自身公网映射，跨网络打洞成功率更高。
- UPnP-IGD / NAT-PMP 自动端口映射：HTTP/HTTPS/中继端口与中继端口段自动映射 + 租约续期，
  并在诊断面板给出映射结果与公网入口链接。
- 自动生成自签名证书（覆盖本机全部地址）→ 默认同时提供 HTTPS 端口，局域网其他电脑也能共享屏幕（安全上下文）。
- 分享地址体系：局域网 IPv4 / 公网 IPv6 / UPnP 公网入口，一键复制或扫码；二维码由服务器本地生成（无外部依赖）。
- 网络初始化完成后自动写日志与托盘菜单，桌面版托盘「复制访问地址」优先复制公网入口。
- 客户端接口：`/api/config`（能力/限制）、`/api/ice`（临时 TURN 凭据，按请求主机匹配可达地址）、
  `/api/network`（诊断，支持 `?deep=1`）、`/api/qr.svg`（二维码）、`/api/health`（健康检查）。
- 冒烟测试扩展为 26 项断言：HTTP 接口 + 房间/共享状态 + 信令转发 + 影院模式码流中继/关键帧/反馈 + 离开清理。

### 修复 / 改进
- WebRTC 候选丢失导致「连不上」：远端描述就绪前的 ICE 候选先缓存再补交；连接失败自动重建（带冷却）。
- ICE 配置在入房前预取，避免新入房的首帧连接缺少中继服务器；TURN 未就绪时自动重试。
- 屏幕共享码率不再「一刀切」：自动档按可用带宽与丢包对每位观看者独立 AIMD 调节，并受总上行预算约束。
- 画质档位改为面向场景：自动（推荐）/ 电影 1080p30 / 游戏 1080p60 / 文字（原生分辨率）/ 省流 720p30。
- 共享停止以服务器状态为准（窗口最小化不会误停），并恢复被静音的其它应用（桌面版窗口声音方案）。

### 移除
- **内置麦克风语音**（v1.4.0 引入，实测无法正常使用）：客户端不再包含麦克风/语音面板相关代码与 UI，
  回归「专注屏幕共享 + 系统声音」；`rooms.js` 同步移除语音状态。
- 客户端不再依赖 ZeroTier / 蒲公英 / 米西 作为主方案（文档保留为高级备选）。

### 工程
- 客户端模块化重组：`core / api / signaling / capabilities / screenshare / webrtc / cinema / stats / stage / ui / panels / main`。
- 服务器新增 `server/net/` 网络能力层：`interfaces / gateway / publicip / turn / tls / doctor`。
- 新增运行时依赖：`turn-server`（STUN/TURN）、`@achingbrain/nat-port-mapper`（UPnP/NAT-PMP）、
  `qrcode-generator`（二维码）、`selfsigned`（自签名证书）。
- **构建链路可复现**：新增 `npm run helper`（从 C# 源码本地编译系统助手）、`scripts/electron-builder.mjs`
  （自动过滤缺失的可选资源 + 默认 npmmirror 镜像加速）；Radmin 安装包变为可选资源，缺失不再导致构建失败。

## [v0.5.1] - 2026-08-10

### 修复
- **VAD 模式麦克风“不工作”根因**：分析器原来接在增益节点之后，VAD 初始静音（gain=0）导致检测器永远读不到信号，形成“检测不到说话 → 一直静音”死锁；改为输入侧直连分析器，静音只影响发送、不影响检测（双端实测确认对端能看到说话光环）
- **本地音量反馈缺失**：自己说话时成员列表的音量条从不填充，已接入 `startLocalMeter`，说话光环 + 实时音量条正常
- **托盘“退出”退不出去**：`shutdown()` 先 `await server.close()`，但内嵌服务器挂着应用自己的 Socket.IO 长连接，回调永远不触发；改为先 `closeAllConnections()` 再 `app.quit()`
- 频道进入改为**双击**，防止误触直接进频道

### 新增
- 应用内退出入口：帮助 → 退出 GinyScreen（桌面版经 IPC 退出）
- 麦克风失败提示更具体：指引检查 Windows 设置 → 隐私 → 麦克风

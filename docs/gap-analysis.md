# Gracs 功能现状与差距（v2.0.0）

> 验证方式：`npm test`（信令 + 影院模式 + HTTP 接口，26 项断言）+ 双浏览器实机联调（画质/链路/诊断/UI）+ 桌面版打包运行。
> 结论：**核心闭环（开房 → 邀请 → 共享 → 观看 → 质量可观测）完整可用**；差距集中在权限、持久化与规模化。

## 二、与主流产品的差距（按优先级）

### P0（影响「用得顺手」）
1. **房主权限**：踢人、锁定房间、共享审批（当前任何人可进可共享）
2. **断线重连体验**：服务器重启后房间状态清空（客户端已能自动重新入房，但共享需重新开始）
3. **单人静音/屏蔽**：屏蔽某人的画面或声音（当前只能调音量/退出）

### P1（高价值）
4. **持久化**：房间状态落盘（JSON/SQLite），服务器重启保留成员列表与设置
5. **本地服务端管理页**：在线人数、中继流量、日志下载
6. **共享增强**：暂停共享、多屏选择记忆、窗口白名单
7. **录制/回放**（本地录制 WebM）

### P2（规模化）
8. **SFU 扩容**（>8 人）：mediasoup，信令协议可复用
9. **账号体系 / 云中继模式**（VPS 跑 TURN/SFU，适合开房者没有公网）
10. **远程控制**（data channel + 虚拟输入）

## 三、技术债与风险

- **mesh 上行**：N 位观看者 = N 路上行；已用「每观看者自适应 + 总预算」缓解，>8 人需 SFU
- **TURN 稳定性**：纯 JS 实现在高并发/大流量下未压测（当前场景足够）；如需生产级可换 coturn（接口已隔离在 `server/net/turn.js`）
- **影院模式浏览器依赖**：WebCodecs 在旧浏览器不可用（自动回退标准链路）
- **无端到端自动化（媒体层）**：目前媒体验证靠双浏览器人工/脚本联调；建议补 Playwright + 合成流量的自动化
- **Electron 体积**：~100MB 级；后续可评估 asar 压缩、按需加载

## 四、验证结论

- 信令 + 影院模式 + HTTP 接口 26/26 断言通过
- 双浏览器实机：局域网/中继两条路径均能观看；影院模式解码渲染正常；诊断与质量面板数据正确
- 建议用户实测点：跨网络（IPv6/公网映射）、多人同时共享、手机扫码观看、桌面版打包与自动更新
